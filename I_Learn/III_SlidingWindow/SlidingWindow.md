# Day 3 滑动窗口（Sliding Window）

> 衔接：Day 1 二分查找 → Day 2 双指针 → **Day 3 滑动窗口**。
> 滑动窗口是双指针的"系统化形态"，专治「连续子数组 / 子串」类问题。今天目标是让你**完全理解它为什么是 O(n)，并能手写出两类模板**。

---

## 一、算法核心思想

**本质**：维护一个区间 `[left, right]`（窗口），让它像一扇窗户一样从左向右滑动；在滑动过程中**动态维护窗口内的关键信息**（如字符种类、元素计数、区间和），从而避免对每个子区间都重新计算（暴力是 O(n²)）。

**两种形态**：

| 形态 | 窗口长度 | left 行为 | 典型题目 |
|------|---------|----------|---------|
| 固定大小窗口 | 固定为 k | 与 right 同步右移 | 长度为 k 的子数组最大平均值（LC643） |
| 可变大小窗口（重点） | 不固定 | right 扩张后，违规时收缩 | 最长无重复子串（LC3）、和≥target 的最短子数组（LC209） |

**核心优势**：right、left 都只向前走、不回退。每个元素最多"进窗口一次、出窗口一次" → 把"枚举所有子区间"的 O(n²) 压成 **O(n)**。可变窗口的精髓一句话概括：

> **right 负责"扩张纳入"，left 负责"收缩恢复合法"；在每次 right 扩张后，用合法窗口更新答案。**

---

## 二、复杂度分析与原因推导

- **时间复杂度：O(n)**
  - 推导依据：left 和 right 都是**单调递增**的指针。right 从 0 走到 n-1 共 n 步；left 也最多从 0 走到 n-1，最多 n 步。二者互不回退，所以总的"指针移动步数" ≤ 2n，与 n 成正比。
- **空间复杂度：O(k) 或 O(1)~O(字符集)**
  - 取决于维护窗口状态所用结构：LC3 用 map 记录字符最近位置，空间为 `min(n, 字符集大小)`；固定窗口仅用几个变量求和，空间 O(1)。
- **对比暴力**：
  - 暴力枚举所有起点 i、终点 j，共 O(n²) 个子区间；若每区间再求和又要 O(n)，总 O(n³)（前缀和优化后 O(n²)）。滑动窗口是**本质性的降维**，而非小修小补。

## 三、核心模板与边界细节

### 可变窗口通用模板（Python 伪码）

```python
left, right = 0, 0
while right < n:
    将 s[right] 纳入窗口      # 更新窗口状态（计数 / 求和 / 记录位置）
    while 窗口不合法:          # 注意是 while 不是 if
        将 s[left] 移出窗口   # 收缩，恢复合法
        left += 1
    # 此时 [left, right] 合法，用它更新答案
    用 right - left + 1 更新 ans
    right += 1
```

**循环不变量（Loop Invariant）**：在每次 `right += 1` 之前，区间 `[left, right]` 始终满足问题定义的"合法条件"（如内部无重复字符）。这就是为什么"收缩"必须放在"更新答案"之前——保证我们用的一定是合法窗口。

**固定窗口模板（长度 k）**：

```python
total = 0
for right in range(n):
    total += s[right]
    if right >= k:
        total -= s[right - k]   # 左边界滑出
    if right >= k - 1:
        用 total 更新答案
```

**易错细节（初学者高频坑）**：

1. **窗口长度 = right - left + 1**（闭区间），漏 `+1` 是最常见的 off-by-one。
2. **收缩用 `while` 而非 `if`**：一次 right 扩张可能引入多个冲突，需连续收缩直到合法。
3. **哈希记"位置"还是"次数"？**
   - LC3 记"字符最近出现下标"，可直接 `left = max(left, pos+1)`；
   - 计数型（如求子串异位词）用 `count[c] += 1 / count[c] -= 1`，凭计数判等。
4. **空串 / 无解边界**：LC3 空串返回 0；LC209 找不到合法子数组返回 0（用 `ans = n+1` 初始化再特判）。
5. **顺序别乱**：先扩张纳入 → 再收缩恢复合法 → 最后用合法窗口更新答案。顺序错会漏算。

## 四、经典实战例题

### 例题 1：LeetCode 3 — 无重复字符的最长子串

**题目描述**：给定字符串 `s`，找出其中不含有重复字符的**最长子串**的长度。

**样例**：
- 输入 `s = "abcabcbb"` → 输出 `3`（子串 `"abc"`）
- 输入 `s = "bbbbb"` → 输出 `1`（子串 `"b"`）
- 输入 `s = "pwwkew"` → 输出 `3`（子串 `"wke"` 或 `"kew"`；注意 `"pwke"` 不是连续子串）

**思路**：维护窗口 `[left, right]` 内无重复字符。用 `last_pos[字符]` 记录其**最近一次出现的下标**。right 每读一个字符 `c`：
- 若 `c` 已在区间内（`last_pos[c] >= left`），说明重复，把 `left` 跳到 `last_pos[c] + 1`；
- 更新 `last_pos[c] = right`；
- 用 `right - left + 1` 更新最长长度。

### 例题 2：LeetCode 209 — 长度最小的子数组

**题目描述**：给定仅含正整数的数组 `nums` 与目标值 `target`，找出和 **≥ target** 的**最短**连续子数组长度；不存在则返回 `0`。

**样例**：
- `nums = [2,3,1,2,4,3]`, `target = 7` → 输出 `2`（子数组 `[4,3]`）
- `nums = [1,4,4]`, `target = 4` → 输出 `1`
- `nums = [1,1,1,1,1,1,1,1]`, `target = 11` → 输出 `0`

**思路**：可变窗口，维护窗口和 `total`。right 扩张累加；一旦 `total >= target`，记录当前长度 `right-left+1` 并更新最小值，然后 **left 右移缩小窗口**（`total` 减去离开元素），继续尝试更短。这是"**先扩张到满足条件，再收缩求最小**"的典型模式。

## 五、代码实现（Python，建议先自己写再看答案）

<details>
<summary>例题 1 答案：LC3 无重复字符的最长子串（Python）</summary>

```python
def length_of_longest_substring(s: str) -> int:
    last_pos = {}          # 字符 -> 最近出现下标
    left = 0
    ans = 0
    for right, c in enumerate(s):
        if c in last_pos and last_pos[c] >= left:
            left = last_pos[c] + 1
        last_pos[c] = right
        ans = max(ans, right - left + 1)
    return ans
```

</details>

<details>
<summary>例题 2 答案：LC209 长度最小的子数组（Python）</summary>

```python
def min_sub_array_len(target: int, nums: list[int]) -> int:
    left = 0
    total = 0
    ans = len(nums) + 1
    for right, val in enumerate(nums):
        total += val
        while total >= target:
            ans = min(ans, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if ans == len(nums) + 1 else ans
```

</details>

## 六、课后进阶思考与方法延伸

**思考题 1（LC3 升级）**：LeetCode 76 *最小覆盖子串* —— 在 `s` 中找包含 `t` 所有字符的**最短**子串。思路：用 `need` 计数 `t` 的字符、`have` 计数窗口内已匹配的字符，当 `have == need` 时收缩求最小。这是可变窗口 + 计数匹配的集大成。

**思考题 2（固定窗口 + 计数）**：LeetCode 438 *找到字符串中所有字母异位词* —— 用固定长度 = `len(p)` 的窗口 + 长度为 26 的计数数组滑窗，每次比较两数组是否相等。

**方法延伸（衔接 Day 4）**：滑动窗口常与"哈希 / 数组计数"搭配；当问题进一步涉及**区间求和、区间差分**时，明天的 **Day 4 前缀和与差分** 会给出 O(1) 区间查询的另一把利器——它常与滑动窗口组合（例如用前缀和瞬间判断某窗口的和是否达标）。掌握今天的可变窗口后，Day 4 你会更快上手。

### 今日一句话总结
滑动窗口 = 双指针 + 循环不变量：**右扩左缩、合法才用、线性扫描**。把"所有子区间"的思维换成"维护一扇会滑的窗"，复杂度从 O(n²) 直接塌到 O(n)。

### 滑动窗口 (Sliding Window) —— ❌ 绝对不能排序
核心要求： 必须保持原数组的物理顺序。

为什么不能排序？ 滑动窗口专门用来解决“连续子数组”或“连续子串”的问题。如果你把数组排序了，原本相邻的元素就被拆散了，求出来的子数组在原数组中根本不连续，这道题就彻底做错了。

它依赖什么？ 它不依赖数组本身有序，但它依赖“**窗口状态的单调性**”。

关联一下你刚做的上一题：为什么包含负数就不能用滑动窗口？因为正常情况下，窗口向右扩大，和一定会增加；左边缩小，和一定会减少（这就是单调性）。有了负数，扩大窗口反而可能变小，滑动窗口就不知道该往哪边滑了。
