## 前缀和（Prefix Sum）—— 就是字面意思，把前面的加起来就叫前缀和

- **解决频繁读取（查询区间和）的痛点**

- 定义：对原数组 a[0..n-1]，构造 pre[0..n]（长度 n+1），其中
    ```python
    pre[0] = 0
    pre[i] = a[0] + a[1] + ... + a[i-1]      （前 i 个元素之和）
    ```
    

- **核心公式（务必背下）**：复用前面的结果数值
    ```python
    sum(a[l..r]) = pre[r+1] - pre[l]          // 闭区间 [l, r]
    ```
本质：一种空间换时间的预处理 —— 把"重复计算的区间求和"提前摊平到一张表里。它的威力在多次查询时才会爆发。

---
## 差分数组（Difference Array）
- **解决频繁写入（修改区间值）的痛点**
- 定义：差分是前缀和的逆运算。对 a[0..n-1]，定义 diff[0..n]（长度 n+1）：
    ```python
    diff[0] = a[0]
    diff[i] = a[i] - a[i-1]     (i >= 1)
    ```
- 核心操作：要把原数组的整个区间 [l, r] 都加上 v，只需两步 O(1)：
    ```python
    diff[l]   += v
    diff[r+1] -= v
    ```
完成后，对 diff 求一次前缀和即可还原出最终数组。
` 为什么成立：对 diff 求前缀和时，diff[l] 处的 +v 会被累计到 a[l] 及之后的所有位置；而 diff[r+1] 处的 −v 从 a[r+1] 开始把这笔增量抵消掉。净效果就是只有 [l, r] 被加了 v。 `
- 二者的对偶关系（非常重要）：
    ```python
    a  ──(求差分)──▶   d  ──(求前缀和)──▶  a     // 一来一回，数组复原
    d  ──(求前缀和)─▶  a  ──(求差分)────▶  d
    ```
记忆法：前缀和 = 区间查询神器；差分 = 区间修改神器。 一个管"查"，一个管"改"。

## Myself
- 这个例子展示了前缀和和差分数组的经典使用方式
    - 通常 前缀和可以单独使用
    - 但是 **差分数组永远无法离开前缀和**


    ```python
        n = len(nums)
        diff = [0] * (n + 1)  # 初始化差分数组，全是 0。长度多 1 为了防止右边界出界
        
        for _ in range(100000):
            # 这里意思只动开头结尾，通过开头结尾影响后面
            diff[101] += 5          # [101] 加一，这样只要往后累加，后面的所有数字就都加5了
            diff[50001] -= 5        # 由于只到50000，所以后面要再减5
            
            diff[2000] -= 3
            diff[80000] -= (-3) 
            
        for k in range(1, n):
            diff[k] += diff[k - 1]  # 核心就是这一次前缀和，把数字像多米诺骨牌传递，获得每一个位置的改变值

        for k in range(n):
            nums[k] += diff[k]      # 把计算好的修改量，一次性加回原数组 (这一步只需要遍历1次！)
    ```

## 前缀和里的哨兵0

**这个首位的哨兵0，不一定必须存在，但强烈建议你永远带着它！**

你完全可以构建一个和原数组**一模一样长**的前缀和数组。但是，如果你选择不加这个哨兵，你以后每次做查询时，都会面临极其恶心的“边界判断”折磨。

可以来对比一下“不加哨兵”和“加哨兵”的真实处境：

- ❌ 痛点：如果不加哨兵（长度为 n）

如果你非要让 `pre` 数组和 `nums` 数组一样长，你的预处理逻辑会变成这样：

    ```python
    nums = [2, 4, 6, 8]
    n = len(nums)

    # 长度一样，没有哨兵
    pre = [0] * n  
    pre[0] = nums[0]  # 第一项必须单独拎出来处理
    for i in range(1, n):
        pre[i] = pre[i-1] + nums[i]
    # 此时 pre = [2, 6, 12, 20]
    ```

现在，你要查询闭区间 `[left, right]` 的和。公式原本应该是 `pre[right] - pre[left - 1]`，**但灾难马上就来了**：

* **正常情况：** 查区间 `[1, 3]`，和是 `pre[3] - pre[0] = 20 - 2 = 18`。没问题。
* **边界情况：** 查区间 `[0, 3]`（也就是从头开始加）。你套用公式：`pre[3] - pre[-1]`,则基本所有语言都不对了。
为了解决这个问题，如果不加哨兵，你每次查询都**必须**写一个 `if/else`：


- ✅ 优雅：加了哨兵之后（长度为 n + 1）

我们在最前面垫上一个 `0`（就像数学里的坐标原点）：
`pre = [0, 2, 6, 12, 20]`

此时你想查区间 `[0, 3]`，套用那句天下无敌的公式：**`pre[right + 1] - pre[left]`**
代入进去就是 `pre[4] - pre[0] = 20 - 0 = 20`。

**没有任何 `if/else` 判断，没有任何越界风险，一行代码统御所有的区间！**

---

- 💡 总结

* **可以没有吗？** 可以，但你需要为此写额外的 `if left == 0` 判断，还会增加写出 Python `-1` 索引 Bug 的风险。
* **最佳实践是什么？** 在算法竞赛和面试中，**99.9% 的选手都会无脑使用 `n + 1` 加哨兵的写法**。它牺牲了一个 `int` （也就是 4 字节）的微小内存，换来的是整个代码逻辑的极度简洁和安全。

所以，把 `pre = [0] * (n + 1)` 刻进 DNA 里，这绝对是这辈子最划算的代码习惯！

## 差分细节

` 假设你现在管理的是一条公交线，发车时车上已经有人了。初始每站人数是 nums = [10, 20, 15]。这时候，如果中途又有一堆预订（区间加减），你该怎么做？`

处理这种“初始有值”的情况，通常有**两种流派**。其实你脑海中想的，非常接近下面的“第二种流派”。我们用具体的数字来推演一遍，你瞬间就能通透了。

假设初始 `nums = [10, 20, 15]`，中途的预订是：**在第 0 站到第 1 站，上来了 5 个人（即区间 `[0, 1]` 增加 5）**。

---

- 流派一：正统差分法（把初始值也当成变化量）

这是算法竞赛中最标准的模板写法。核心思想是：**把初始数组也看作是从全 0 变过来的。**

1. **根据 `nums` 预先构建完整的 `diff`（求差）：**
* `diff[0] = nums[0] = 10`
* `diff[1] = nums[1] - nums[0] = 20 - 10 = 10`
* `diff[2] = nums[2] - nums[1] = 15 - 20 = -5`
* 现在，完整的差分数组是 **`diff = [10, 10, -5]`**。


2. **处理后来的预订（区间加减）：**
* 区间 `[0, 1]` 加 5：
* `diff[0] += 5` 👉 变成 `15`
* `diff[1 + 1] -= 5` 👉 `diff[2] -= 5` 变成 `-10`
* 修改后的差分数组是 **`diff = [15, 10, -10]`**。


3. **对 `diff` 求前缀和，直接得到最终结果：**
* `res[0] = 15`
* `res[1] = 15 + 10 = 25`
* `res[2] = 25 + (-10) = 15`
* **最终真实的 `nums` 就是 `[15, 25, 15]**`。（对比原来的 `[10, 20, 15]`，确实前两站多了 5 个人，完美！）



---

- 流派二：增量分离法（可能正是你脑海里的思路）

这种方法更符合直觉，意思是：**“原来的归原来的，变化的归变化的，最后加在一起。”**

1. **先把 `nums = [10, 20, 15]` 原封不动放在一边。**
2. **建一个全 0 的新 `diff`，只处理新的预订：**
* 就像上一题一样，区间 `[0, 1]` 加 5：
* `diff[0] += 5`
* `diff[2] -= 5`
* 此时 `diff = [5, 0, -5]`


3. **对这个新的 `diff` 求前缀和，得到一个“纯变化量数组”：**
* `changes[0] = 5`
* `changes[1] = 5 + 0 = 5`
* `changes[2] = 5 + (-5) = 0`
* 得到变化量：`changes = [5, 5, 0]`。


4. **把“原始值”和“变化量”对应位置相加：**
* `10 + 5 = 15`
* `20 + 5 = 25`
* `15 + 0 = 15`
* **最终结果依然是 `[15, 25, 15]**`。

---

- 总结

你的那句“先求 prefix 已有值”其实是个口误，你的意思应该是“先保留原本的 nums，单独算差分的变化量，然后再把它加回原本的 nums 上”**，也就是我说的**流派二！

这两个流派在时间复杂度上都是极速的 $O(N)$，数学本质也完全等价（因为加法符合分配律：`初始值 + 变化量 = 最终值`）。

但在实际刷题或者工程中，**大家更推荐写“流派一”**。因为它只维护了一个 `diff` 数组，代码更短，也不用最后再搞一个循环去把两个数组加起来。
