# Day 5 单调栈与单调队列（Monotonic Stack & Monotonic Queue）

> 学习路线：Day 1 二分查找 → Day 2 双指针 → Day 3 滑动窗口 → Day 4 前缀和与差分 → **Day 5 单调栈与单调队列** → Day 6 链表核心技巧
> 一句话定位：**当一个元素"再也没机会成为答案"时，就永久删除它**。用栈维护"还没找到答案的候选人"，用队列维护"窗口内还有竞争力的候选人"。
> 前置衔接：Day 3 的滑动窗口把 O(n²) 压成 O(n)，但它只能回答"窗口的和/长度"这类**可增量撤销**的指标；一旦问"窗口内的**最大值**"（删掉的元素如果是最大值就没法撤销），滑动窗口就失效了。今天的主角正是来解决这个问题的。

## 〇、先来一个最小例子（建立直觉）

**问题**：数组 `a = [73, 74, 75, 71, 69, 72, 76, 73]`，对每个位置回答：**右边第一个比我大的数离我多远？**

**暴力做法**：每个位置都向右扫描直到找到更大的数 → 最坏 O(n²)。比如全是递减的数组 `[7,6,5,4,3,2,1]`，每个位置都要一路扫到底，一次都找不到。

**换个思路（关键洞察）**：想一想，什么时候我能确定 `a[i]` 的答案？

答案是：**当我从右往左（或从左往右）遇到第一个比 `a[i]` 大的数时**。在那之前，`a[i]` 的答案都还悬着。

于是我们维护一个"**悬而未决者名单**"——一个栈，里面存着**还没找到答案**的元素：

| 扫描到 | 当前值 v | 栈内（存下标） | 动作 |
|--------|---------|---------------|------|
| i=0 | 73 | `[]` | 没有比它小的悬着，入栈 → `[0]` |
| i=1 | 74 | `[0]` | 74 > 73，**i=0 的答案找到了**（距离 1-0=1），弹栈！→ `[1]` |
| i=2 | 75 | `[1]` | 75 > 74，i=1 答案是 1，弹栈 → `[2]` |
| i=3 | 71 | `[2]` | 71 < 75，不弹，入栈 → `[2,3]` |
| i=4 | 69 | `[2,3]` | 69 < 71，不弹，入栈 → `[2,3,4]` |
| i=5 | 72 | `[2,3,4]` | 72 > 69 → 弹 4（距离 5-4=1）；72 > 71 → 弹 3（距离 5-3=2）；72 < 75 → 停，入栈 → `[2,5]` |
| i=6 | 76 | `[2,5]` | 76 > 72 → 弹 5（距离 1）；76 > 75 → 弹 2（距离 4）；入栈 → `[6]` |
| i=7 | 73 | `[6]` | 73 < 76，入栈 → `[6,7]` |

最终答案 `[1,1,4,2,1,1,0,0]`，栈里剩下的 `[6,7]` 就是**永远没等到更高温的日子**，答案保持 0。

**关键发现**：每个元素**最多入栈一次、出栈一次**，总共 2n 次操作 → **O(n)**。这就是单调栈的全部威力。

<details>
<summary>最小例子的 Python 实现</summary>

```python
def daily_distances(a):
    ans = [0] * len(a)
    st = []                       # 存下标，对应的值严格递减
    for i, v in enumerate(a):
        while st and v > a[st[-1]]:      # 我是"第一个更大者"
            j = st.pop()                 # 结算 j 的答案
            ans[j] = i - j
        st.append(i)
    return ans

a = [73, 74, 75, 71, 69, 72, 76, 73]
print(daily_distances(a))   # [1, 1, 4, 2, 1, 1, 0, 0]
```

</details>

## 一、算法核心思想

### 1.1 单调栈（Monotonic Stack）

**定义**：栈内元素始终保持**单调递增**或**单调递减**的顺序。不满足时，从栈顶弹出直到重新满足单调性。

**两种形态（必须分清）**：

| 形态 | 栈内顺序（底 → 顶） | 求的是什么 |
|------|-------------------|-----------|
| **单调递减栈** | 大 → 小 | 每个元素**右边/左边第一个更大**的元素（Next Greater） |
| **单调递增栈** | 小 → 大 | 每个元素**右边/左边第一个更小**的元素（Next Smaller） |

> 记忆口诀：**"求更大用递减栈，求更小用递增栈"**。
> 逻辑：想找"更大的"，就把小的先堆在栈顶，等一个大的来把它们全踢走。

**核心心法（比模板更重要）**：

> **栈里存的是"还不知道答案的人"，一旦新元素能让某些人确定答案，就立刻弹栈结算，然后自己入栈等待。**

这条心法解释了三件事：
1. 为什么要**循环弹**（while 不是 if）？—— 一个新人可能同时是多个悬着者的答案（上表中 i=5 一次弹了两个）。
2. 为什么是 O(n)？—— 每人只进一次、只出一次。
3. 为什么最后栈里可能剩下人？—— 他们**永远等不到答案**，用默认值（0 或 -1）填充。

### 1.2 单调队列（Monotonic Queue）

**定义**：一个**双端队列（deque）**，队首到队尾保持单调，且同时维护"元素不过期"。它是**单调栈 + 滑动窗口**的结合体。

**它解决什么问题**：滑动窗口内的**最大值 / 最小值**。

回顾 Day 3 的教训：窗口滑动时，如果窗口内维护的是"和"，删掉一个元素只需减去它，可以**增量撤销**；但如果维护的是"最大值"，删掉的恰好是最大值时，你**无法撤销**——你不知道第二大是谁。单调队列就是为此设计的。

**两条删除规则（缺一不可）**：

```
规则一（队尾淘汰）：新元素 x 进队前，从队尾踢掉所有 < x 的元素。
规则二（队首过期）：若队首下标 ≤ i - k，说明它已滑出窗口，从队首弹出。
```

**为什么规则一成立（这是全篇最精妙的一句）**：

> 假设队尾有个老元素 `y`，新元素 `x` 满足 `y ≤ x`。那么 `y` 同时具备两个劣势：
> ① **值更小**（`y ≤ x`，在求最大值时永远轮不到它）；
> ② **更早过期**（`y` 在 `x` 左边，会先滑出窗口）。
>
> 一个既不够大、又活得更短的元素，**在任何未来窗口里都不可能成为答案** → 可以永久删除，毫无损失。

这叫**支配关系（domination）**：`x` 完全支配 `y`。删除被支配者，是单调队列能做到 O(n) 的根本原因。

### 1.3 三者能力对照表（什么时候用谁）

| 问题类型 | 工具 | 复杂度 | 备注 |
|---------|------|--------|------|
| 区间求和（多次查询、无修改） | 前缀和（Day 4） | O(1)/次 | 不能处理修改 |
| 区间整体增减（离线批量） | 差分（Day 4） | O(1)/次 | 最后统一还原 |
| 窗口内**可撤销**指标（和、长度、计数） | 滑动窗口（Day 3） | O(n) | 最大值不可撤销 |
| **下一个更大/更小元素** | 单调栈 | **O(n)** | 一维扫描 |
| **窗口内最大值/最小值** | 单调队列 | **O(n)** | 窗口 + 最值 |
| 区间最值（任意区间查询） | 线段树 / ST 表 | O(log n) / O(1) | 进阶内容 |

**选型口诀**：

- 看到「**下一个更大 / 更小**」「**左边第一个小于我的**」「**视野更广阔的**」→ **单调栈**
- 看到「**滑动窗口最大值**」「**长度不超过 k 的子数组最值**」→ **单调队列**
- 看到「**最大矩形 / 最大面积**」「**柱状图**」→ **单调栈**（LC84）

## 二、复杂度分析与原因推导

### 2.1 单调栈的复杂度

| 项目 | 结论 | 推导依据 |
|------|------|---------|
| 时间复杂度 | **O(n)** | 每个下标**恰好入栈一次**；被弹出后就再也不会回来，**最多出栈一次**。while 循环的总执行次数 ≤ n（不是每轮 n 次）。故总操作数 ≤ 2n。 |
| 空间复杂度 | **O(n)** | 最坏情况（数组严格递减）所有元素都在栈里，无人被弹出。 |

**为什么不是 O(n²)？** 这是初学者最常犯的误判。嵌套的 `for + while` 看起来像 O(n²)，但**摊还分析（Amortized Analysis）**告诉我们：while 循环体在整个算法生命周期内总共只执行 n 次。判断依据是"**每个元素只进栈一次、出栈一次**"，而不是"每层循环里 while 最多跑几次"。

### 2.2 单调队列的复杂度

| 项目 | 结论 | 推导依据 |
|------|------|---------|
| 时间复杂度 | **O(n)** | 同单调栈：每个下标入队一次、出队一次，队尾淘汰与队首过期的总次数均 ≤ n。 |
| 空间复杂度 | **O(k)** | 队列最多保存一个窗口的元素，窗口大小为 k。 |

**实现陷阱（重要）**：

- **Python**：必须用 `collections.deque`。用 `list.pop(0)` 删队首是 **O(k)**，会让整体退化成 O(n·k)。
- **Go**：`slice[1:]` 重切是 O(1)，可接受；若追求极致可用数组模拟环形队列避免底层数组无法回收。
- **Java**：用 `ArrayDeque`，不要用 `LinkedList`。

## 三、核心模板与边界细节

### 3.1 单调栈通用模板（求"下一个更大元素"）

```
st = []                          // 存下标（存下标才能算距离）
for i = 0 .. n-1:
    while st 非空 且 a[i] > a[st.top]:     // ① 循环弹，不是 if
        j = st.pop()                        // ② 结算 j
        ans[j] = i - j        （或 a[i]，取决于题目问距离还是值）
    st.push(i)                              // ③ 自己入栈等待
// 结束后 st 里剩下的是"永远等不到答案的"，ans 保持默认值 0 / -1
```

### 3.2 单调队列通用模板（求"滑动窗口最大值"）

```
q = deque()                      // 存下标（存值无法判断是否过期！）
for i = 0 .. n-1:
    // ① 队尾淘汰：踢掉所有 ≤ a[i] 的（它们被 a[i] 支配）
    while q 非空 且 a[i] >= a[q.back]:
        q.pop_back()
    q.push_back(i)
    // ② 队首过期：下标 ≤ i-k 的已滑出窗口
    if q.front <= i - k:
        q.pop_front()
    // ③ 窗口形成后（i >= k-1），队首就是答案
    if i >= k-1:
        ans.append(a[q.front])
```

> **注意顺序**：先入队再判过期，或先判过期再入队都可以，但**必须保证下标不越界**。上面的写法先入后判，逻辑最清晰。

### 3.3 六大易错细节（逐条对照检查）

| # | 易错点 | 说明与对策 |
|---|--------|-----------|
| 1 | **存值还是存下标** | 「求下一个更大**值**」（LC496）可存值；「求距离」（LC739）、「求窗口最值」（LC239）**必须存下标**。拿不准就一律存下标。 |
| 2 | **`>` 还是 `>=`** | 遇到**相等**元素时：用 `>` 保留相等者（栈内**非严格**单调）；用 `>=` 踢掉相等者（栈内**严格**单调）。多数题目两者都对，但 LC84 求面积时会影响结果正确性，需小心。**默认用 `>`（保留），更安全**。 |
| 3 | **`while` 不是 `if`** | 一个元素可能同时是多个悬着者的答案。写成 `if` 会漏解。 |
| 4 | **环形数组遍历长度** | LC503 遍历 `2n` 次即可（实践中 `2n-1` 也够，但 `2n` 更好记、更安全）。关键是**第二轮只弹不入**（`if i < n` 才入栈），避免重复入栈导致答案错乱。 |
| 5 | **哨兵技巧** | LC84 在原数组末尾补一个 **0**（右哨兵），强制在循环结束时清空栈，**省掉"收尾清算"那段重复代码**。同理可在开头补哨兵。这是最实用的简化技巧。 |
| 6 | **收尾清算别忘** | 若不用哨兵，循环结束后栈里剩下的元素需要单独处理（弹出并结算，右边界取 n）。忘了这步是 LC84 最常见的 WA 原因。 |

### 3.4 循环不变量（Loop Invariant）

写代码时脑中保持这两条，能立刻判断代码对不对：

- **单调栈**：循环到第 `i` 步时，栈中下标对应的值**严格单调递减**；且栈中任意元素**都还没找到**「右边第一个更大者」。
- **单调队列**：循环到第 `i` 步时，队列中下标**严格递增**，对应的值**严格递减**；且队首一定是**当前窗口 `[i-k+1, i]` 的最大值**。

### 例题 1：LeetCode 739 — 每日温度（中等）· 单调栈入门

**题目描述**：给定每天温度的数组 `temperatures`，返回一个数组 `answer`，其中 `answer[i]` 表示「第 `i` 天之后，需要等多少天才能等到更高温度」。若之后都不会升高，则为 `0`。

**样例**：

```
输入：temperatures = [73,74,75,71,69,72,76,73]
输出：[1,1,4,2,1,1,0,0]
解释：第 0 天 73°，第 1 天 74° 更高，只需等 1 天。
     第 2 天 75°，要等到第 6 天的 76°，等 4 天。
```

**思路**：这就是第〇节的最小例子本身。

1. 栈中存**下标**，对应温度**严格递减**（求"更大" → 递减栈）。
2. 扫描每个 `i`，若 `t[i] > t[栈顶]`，说明**今天就是栈顶那天的"更高温度"** → 弹栈并结算 `ans[j] = i - j`。
3. 循环弹完后自己入栈。
4. `ans` 初始化为全 0，栈里剩下的自然就是 0，**无需收尾清算**。

**关键点**：`ans` 用 0 初始化这一设计，让"等不到"的情况自动成立——这是初始化默认值的小技巧。

### 例题 2：LeetCode 496 — 下一个更大元素 I（简单）· 哈希 + 单调栈

**题目描述**：`nums1` 是 `nums2` 的子集。对 `nums1` 中每个元素 `x`，找出它在 **`nums2` 中** `x` 右侧第一个比 `x` 大的元素；不存在则 `-1`。

**样例**：

```
输入：nums1 = [4,1,2], nums2 = [1,3,4,2]
输出：[-1,3,-1]
解释：4 在 nums2 中右侧没有更大的 → -1
     1 右侧第一个更大的是 3 → 3
     2 右侧没有更大的 → -1
```

**思路**：

1. 先对 **`nums2`** 跑一遍标准单调栈，求出 `nums2` 中**每个值**的下一个更大元素，结果存进哈希表 `mp[值] = 下一个更大值`（题目保证无重复元素，可直接存值）。
2. 再遍历 `nums1`，查表即可。
3. `mp` 中查不到的，答案就是 `-1`。

**关键点**：这是"**离线预处理 + 查表**"的典型模式。注意这里存**值**而非下标，因为题目问的是"值是多少"而不是"距离多远"。

### 例题 3：LeetCode 503 — 下一个更大元素 II（中等）· 环形数组

**题目描述**：同上，但数组是**环形**的——最后一个元素的下一个是第一个元素。求每个元素的下一个更大元素（值，非距离）。

**样例**：

```
输入：nums = [1,2,1]
输出：[2,-1,2]
解释：第 0 个 1，后面是 2，更大 → 2
     第 1 个 2，绕一圈也没有比 2 更大的 → -1
     第 2 个 1，绕回第 0 个还是 1（不更大），再走到第 1 个 2 → 2
```

**思路（关键：把环拆成链）**：

1. 遍历 `2n` 次，用 `idx = i % n` 取模实现环形访问。
2. **第二轮只弹不入**：`if i < n { 入栈 }`。因为第一轮已经把所有下标入过一次；第二轮若再入栈，会导致同一个下标被重复结算，答案错乱。
3. `ans` 初始化为 `-1`，等不到的自动保持 `-1`。

**关键点**：为什么遍历 `2n` 次就一定够？因为环上每个元素最多绕一圈就能找到答案（最大元素除外，它永远找不到）。

### 例题 4：LeetCode 84 — 柱状图中最大的矩形（困难）· 单调栈进阶

**题目描述**：给定 `n` 个非负整数表示柱状图各柱子的高度，每个柱子宽度为 1，求其中**能勾勒出的最大矩形面积**。

**样例**：

```
输入：heights = [2,1,5,6,2,3]
输出：10
解释：最大矩形由高度 5 和 6 两根柱子构成，宽 2 高 5，面积 = 2×5 = 10
```

**思路（全篇最需要理解的一题）**：

核心转变思路：暴力枚举"左右边界"是 O(n²)。换一个角度——**枚举每根柱子作为矩形的「高度」**（即以它为最矮的柱子），然后问：**以它为中心，最宽能向左右扩展到哪里？**

答案是：**扩展到左、右两边「第一个比它矮」的柱子为止**。因为一旦遇到更矮的，矩形高度就会被压低，不再属于"以当前高度为高"的矩形。

于是问题转化为：对每个 `i`，求「左边第一个更小」和「右边第一个更小」→ 典型的**单调递增栈**。

**算法流程**：

1. 维护**单调递增栈**（存下标，高度递增）。
2. 当遇到 `h[i] < h[栈顶]` 时，说明**找到了栈顶柱子的右边界**（就是 `i`），此时栈顶的左边界是**弹出后的新栈顶**（即 `st[-1] + 1`）。
3. 结算宽度与面积：
   ```
   高度 = h[top]
   右边界 = i - 1
   左边界 = st[-1] + 1 （若栈空则为 0）
   宽度 = 右边界 - 左边界 + 1 = i - st[-1] - 1   （栈空时宽度 = i）
   面积 = h[top] × 宽度
   ```
4. **哨兵技巧**：在原数组末尾补一个高度 0（右哨兵）。因为 0 比任何高度都小，它会把栈里所有人全部弹干净，**自动完成收尾清算**，代码里就不需要单独写"循环结束后处理剩余元素"那段了。

**宽度公式推导（务必理解，不要死记）**：

```
栈中：[... , 左边界-1(即 st[-1]), top, ...]
       ↑                          ↑
      左边界 = st[-1]+1        右边界 = i-1

宽度 = (i-1) - (st[-1]+1) + 1 = i - st[-1] - 1
```

**关键点**：
- 栈**必须单调递增**，相等时也要入栈（所以用 `<` 而非 `<=` 判断），这样相等高度的柱子会一起被正确结算。
- 栈空时宽度取 `i`（左边界是 0）。

### 例题 5：LeetCode 239 — 滑动窗口最大值（困难）· 单调队列

**题目描述**：给定数组 `nums` 和窗口大小 `k`，窗口每次右移一位，返回每个窗口中的最大值。

**样例**：

```
输入：nums = [1,3,-1,-3,5,3,6,7], k = 3
输出：[3,3,5,5,6,7]
解释：[1 3 -1] 最大 3；[3 -1 -3] 最大 3；[-1 -3 5] 最大 5；
      [-3 5 3] 最大 5；[5 3 6] 最大 6；[3 6 7] 最大 7
```

**思路**：这正是 Day 3 滑动窗口**解决不了**的问题——删掉的元素如果恰好是最大值，无法撤销。改用单调队列：

1. 队列存**下标**，对应值**递减**。
2. **入队前队尾淘汰**：`while nums[i] >= nums[q.back] { q.pop_back() }`。理由：被踢掉的元素既比 `nums[i]` 小，又比它早过期，**被完全支配，永远不会成为答案**。
3. **队首过期**：`if q.front <= i - k { q.pop_front() }`。
4. `i >= k-1` 时，队首就是当前窗口最大值。

**为什么队首一定是最大值？** 因为队列保持递减，队首是**窗口中最大的元素**；而队首又没过期，所以它确实在当前窗口内。两条合起来 → 队首 = 窗口最大值。

**关键点**：
- Python 用 `deque`，**禁止** `list.pop(0)`。
- 队列里存**下标**不是值——只有下标才能判断是否过期。
- 用 `>=` 踢掉相等元素（保留更"新"的），保证队列严格递减，避免相等元素堆积。

<summary>例题 1 · LC739 每日温度 — 解答</summary>

```python
# ========== LC739 每日温度：单调递减栈 ==========
def dailyTemperatures(t: List[int]) -> List[int]:
    n = len(t)
    ans = [0] * n                     # 默认 0：等不到更高温度的自动为 0
    st: List[int] = []                # 存下标，对应温度严格递减
    for i, v in enumerate(t):
        while st and v > t[st[-1]]:   # 注意：while 不是 if
            j = st.pop()
            ans[j] = i - j
        st.append(i)
    return ans
```

# ========== LC496 下一个更大元素 I：哈希 + 单调栈 ==========
def nextGreaterElement(nums1: List[int], nums2: List[int]) -> List[int]:
    mp: dict[int, int] = {}
    st: List[int] = []
    for v in nums2:
        while st and v > st[-1]:
            mp[st.pop()] = v
        st.append(v)
    return [mp.get(v, -1) for v in nums1]

# ========== LC503 下一个更大元素 II：环形数组 ==========
def nextGreaterElements(nums: List[int]) -> List[int]:
    n = len(nums)
    ans = [-1] * n
    st: List[int] = []
    for i in range(2 * n):            # 遍历两圈
        idx = i % n
        v = nums[idx]
        while st and v > nums[st[-1]]:
            ans[st.pop()] = v
        if i < n:                     # 第二轮只弹不入
            st.append(idx)
    return ans
```

# ========== LC84 柱状图最大矩形：单调递增栈 + 右哨兵 ==========
def largestRectangleArea(h: List[int]) -> int:
    a = h + [0]                       # 右哨兵：高度 0，强制清空栈
    st: List[int] = []
    ans = 0
    for i in range(len(a)):
        while st and a[i] < a[st[-1]]:        # 用 < 保证相等高度不被误弹
            top = st.pop()
            width = i if not st else i - st[-1] - 1
            ans = max(ans, a[top] * width)
        st.append(i)
    return ans
```

<summary>例题 5 · LC239 滑动窗口最大值 — 解答</summary>

```python
# ========== LC239 滑动窗口最大值：单调递减队列 ==========
def maxSlidingWindow(nums: List[int], k: int) -> List[int]:
    q: deque[int] = deque()           # 必须用 deque！list.pop(0) 是 O(n)
    for i in range(k):                # 先装满第一个窗口
        while q and nums[i] >= nums[q[-1]]:   # 队尾淘汰
            q.pop()
        q.append(i)
    ans = [nums[q[0]]]
    for i in range(k, len(nums)):
        while q and nums[i] >= nums[q[-1]]:
            q.pop()
        q.append(i)
        if q[0] <= i - k:             # 队首过期出队
            q.popleft()
        ans.append(nums[q[0]])
    return ans
```

### 6.1 拓展思考题（建议按序完成）

**思考题 1：LeetCode 42 — 接雨水（困难）**
> 你在 Day 2 用**双指针**做过这道题。现在请用**单调栈**重新实现一遍。
>
> 提示：双指针是**按列求**（每列能接多少水），单调栈是**按行求**（遇到一个"右墙"时，结算它和"左墙"之间的凹槽，横向一层一层地加水）。
> 关键：维护**单调递减栈**，当 `h[i] > h[栈顶]` 时弹出 `top`，此时左墙是新的栈顶、右墙是 `i`，水深 = `min(h[左墙], h[i]) - h[top]`，宽度 = `i - 左墙 - 1`。
>
> 这道题的价值：同一问题两种范式对比，能帮你彻底理解"什么时候用双指针、什么时候用单调栈"。**双指针需要两端向中间收敛的对称性，单调栈则处理"凹槽/配对"结构。**

**思考题 2：LeetCode 1438 — 绝对差不超过限制的最长连续子数组（中等）**
> 给你一个数组 `nums` 和整数 `limit`，求最长连续子数组的长度，使得子数组内**任意两元素的绝对差 ≤ limit**（即 `最大值 - 最小值 ≤ limit`）。
>
> 提示：这是 **Day 3 滑动窗口 + Day 5 单调队列**的完美结合——
> - 外层用滑动窗口维护合法区间 `[left, right]`；
> - 用**单调递减队列**维护窗口最大值，用**单调递增队列**维护窗口最小值；
> - 每当 `最大值 - 最小值 > limit`，右移 `left` 并让两个队列的过期队首出队。
>
> 这道题的价值：你会真切体会到 Day 3 的困境——**窗口最值无法增删改**，必须靠单调队列补位。做完它，Day 3 和 Day 5 就打通了。

**思考题 3（选做）：LeetCode 901 — 股票价格跨度（中等）**
> 设计一个数据结构，每来一个新价格，返回「**连续**多少天（含今天）的价格 ≤ 今天的价格」。
>
> 提示：单调**递减**栈，栈中存 `(价格, 跨度)` 对。每来一个价格，把栈中 ≤ 它的跨度累加起来合并。这是单调栈在**在线数据流**场景的经典应用。

### 6.2 方法延伸

| 延伸方向 | 说明 |
|---------|------|
| **单调栈优化 DP** | 某些 DP 的状态转移形如 `dp[i] = min(dp[j] + cost(j,i))`，可用单调队列优化到 O(n)，即「**单调队列优化 DP**」，是 Day 9 动态规划的重要加速手段。 |
| **字典序最小问题** | 如 LC316「去除重复字母」、LC402「移掉 K 位数字」，本质是**单调递增栈 + 贪心**：遇到更小的就把前面大的踢掉，这是单调栈在贪心领域的分支。 |
| **并查集 + 单调栈** | LC84 有一类变体需要配合并查集做路径压缩，属于竞赛向进阶内容。 |
| **与线段树的取舍** | 单调队列只能处理**滑动窗口**（固定/单调移动的区间）最值；任意区间最值查询需上**线段树**或 **ST 表**（后续安排）。 |

### 6.3 下一天预告：Day 6 链表核心技巧

**为什么紧接着学链表？** 有三条直接的知识依赖：

1. **数据结构层面的承接**：今天用的单调队列，其底层就是一个**双端队列（deque）**，而 deque 的经典实现之一正是**双向链表**。你会好奇"为什么 Go 的 `slice[1:]` 能 O(1) 删队首，而 Python 的 `list.pop(0)` 却是 O(n)"——答案就在链表的内存布局里。
2. **算法技巧的复用**：Day 2 学过的**双指针**，在链表上会演化出最经典的形态——**快慢指针**（判环、找中点、找倒数第 k 个）。这是双指针思想的第二次出场。
3. **思维模式的转换**：前五天我们操作的都是**数组**（支持 O(1) 随机访问），链表则**只能顺序访问**。这个根本差异会强迫你重新审视"哪些操作是廉价的"，是数据结构思维的一次重要升级。

**Day 6 核心内容预告**：虚拟头节点（dummy head）技巧、快慢指针三大应用、链表反转（迭代 + 递归）、合并与分割、环形链表检测（Floyd 判环算法及其数学证明）。
